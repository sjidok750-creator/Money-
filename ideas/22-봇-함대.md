# 22. 봇 함대 — "나 대신 여러 봇이 계속 벌려고 애쓰는 구조" (2026-09-02)

사용자: "봇이 계속 내 자산을 불리려 노력하고 있다면 언젠가 어떤 봇이든 먼저 벌어오지 않을까. 만 원은 상징이었다. 이익 실현이 목적이다."

## 이 논리가 성립하는 조건 (먼저 못 박는다)
"여러 마리를 굴리면 하나는 번다"는 레벨스의 12 startups 논리와 같다. 단, 네 조건이 있다:
1. **각 봇의 기대값이 0 이상**이어야 한다. 마이너스 봇을 여러 마리 굴리면 더 빨리 잃는다. 봇을 늘리는 것은 확률을 늘리는 것이지 기대값을 늘리는 게 아니다
2. **서로 다른 것에 베팅**해야 한다. 코인 봇 5마리는 봇 1마리다(전부 코인 시장에 묶임). 시장 봇·구조 봇·공장 봇을 섞어야 함대다
3. **운영비가 0에 가까워야** 한다. VPS $5, Claude 세션, 사람 시간 월 몇 시간
4. **죽이는 규칙**이 있어야 한다. 실현 원화가 유일한 점수. 8주 안에 실현 0이면 접는다

## 실현의 정의와 원장
- 점수 = **실현 원화**만. 미실현 평가익·포인트·크레딧은 별도 열
- 각 봇마다 `journal/`에 주간 한 줄: 투입 자본/시간, 실현 원화, 누적, 판정
- 죽이는 규칙: 8주 실현 0 → 접는다. 단 A(시장 봇)은 장세 변수라 12주 + BuyHold 대비 우위로 판정 (HANDOVER 규칙)
- 키우는 규칙: 실현이 생긴 봇에만 자본·시간을 더 준다. 검증 없는 증액 금지

## 시장 봇에 대한 냉정한 한 줄
A종은 아무리 늘려도 자본 100만 원에서는 연 10~30만 원이 상한이다. A종의 역할은 "먼저 벌어오는 봇"이 아니라 **낙폭을 줄이며 자본을 지키는 것**이고, 먼저 벌어올 가능성이 높은 건 B·C종이다. B종은 상대가 귀찮은 사람이고, C종은 장터가 유통을 대신하기 때문이다.

## 이번 주 실행 순서
1. (사용자, 10분) VPS에서 `mr.py`를 `~/Trade/backtest/`에 복사 → `python -m backtest.mr` 와 `combo` 실행 → 결과 붙여주기. 합성 50/50이 추세 단독보다 MDD가 낮고 샤프가 높으면 2번 봇 채택
2. (사용자, 2분) 빗썸 예치금 이용료 "즉시 받기" 신청 → 첫 실현 원화 (금액은 작지만 함대 원장 1번 기록)
3. (Claude, 승인 시) 5번·10번 Routine 생성: 매주 월요일 공모전 수집 + 함대 원장 정리. 사용 요금이 드는 결정이라 사용자 승인 후
4. (Claude, 다음 세션) 4번 공모주 판정 봇 코드 작성 (VPS 실행, 텔레그램 알림). 이 환경은 데이터 사이트가 막혀 있어 사용자 VPS에서 검증
5. 7·8번 공장 봇은 시도 #4·#5 승인과 함께 시작

- 거래소 간 차익 봇: 스프레드 < 왕복 수수료 0.09%, 봇 속도전
- 고빈도 그리드(분봉): 첫 백테스트에서 비용만 -60%. 일봉 딥 바이(2번)로 대체

- 오픈소스 바운티 봇: 봇끼리 경쟁
